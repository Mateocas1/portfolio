ofertaSUPER

Comparador de precios de supermercados argentinos

Compara precios de 5 supermercados argentinos, unos 23.000 productos y 40.000 ofertas que se actualizan a diario con USD 0 de infraestructura, empareja productos por código EAN y permite armar una canasta para comparar entre tiendas.

Volver al portfolio Repositorio

El problema

Comparar precios exige confianza del dato, no solo interfaz.

Un precio comparado solo sirve si el producto es el mismo y el dato está al día: la base del proyecto es un refresh diario con controles de calidad y el emparejamiento por EAN.

Datos 5 supermercados, refresh diario

Carrefour, Coto, Disco, Jumbo y Vea: los datos llegan desde la API de VTEX y la búsqueda de Coto, y los productos se emparejan por código EAN.

Construcción Next.js, PostgreSQL y Redis

Next.js y TypeScript; APIs REST públicas (búsqueda, productos, historial de precios y lote) servidas desde un snapshot JSON versionado, sin base de datos en el camino de lectura, con rate limiting en Redis y panel de administración con Clerk.

Calidad CI en cada cambio

304 pull requests integrados con GitHub Actions: lint, typecheck, 685 tests, build y Lighthouse, con 100/100 en accesibilidad y SEO.

Operación Refresh programado

Un job de GitHub Actions restaura el estado de PostgreSQL, refresca el catálogo con controles de frescura, publica el snapshot y manda un resumen de bajas de precio por Telegram.

Flujo de datos

De la API de VTEX a la comparación.

Fuente API de VTEX

API de VTEX y búsqueda de Coto: productos y ofertas de 5 supermercados.

Ingesta GitHub Actions

El refresh diario corre como job programado, con controles de frescura antes de publicar.

Emparejamiento Código EAN

Los productos se emparejan entre tiendas por EAN.

Catálogo PostgreSQL

PostgreSQL y Prisma sostienen productos, precios e historial; el estado se restaura y se vuelve a guardar en cada refresh.

Consumo APIs REST públicas

Búsqueda, productos, historial de precios y lote, desde un snapshot versionado y con rate limiting en Redis.
